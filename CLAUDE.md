# Ball Ball Manager — notes for Claude

## Always ship to the live site
The game is played from GitHub Pages: https://ceyanang.github.io/ball-ball-manager/
The owner has given standing permission to update `main` so the site stays current.

After finishing any piece of work (and once `npm test` and `npm run typecheck` pass):
1. Commit on the working branch and push it.
2. Fast-forward/merge that work into `main` and `git push origin main` — this triggers `.github/workflows/deploy.yml`, which tests, builds and deploys Pages.
3. Check the "Deploy to GitHub Pages" workflow run finished green; if it failed, fix it before calling the work done.
4. Tell the owner the site is updated (the installed phone app picks up the new version on its next launch with signal).

Never deploy a red build: the workflow runs the tests, but run them locally first.

## Project basics
- React + TypeScript + Vite app; pure-TS engine in `src/engine/` (no React/DOM/Math.random — use `Rng`).
- `npm test` (Vitest), `npm run typecheck`, `npm run dev`, `npm run build`.
- Spec: `docs/superpowers/specs/2026-11-22-ball-ball-manager-design.md`; plans in `docs/superpowers/plans/` (M1 core league, M2 GM layer, M3 stories, rivalries and MyCareer slice A done).
- Fans: `fans.players` is short-term game buzz, `fans.base` the long-term following (tenure, homegrown, team hopping, stardom, form, relative +/-, hardware) recomputed weekly in `stories/sentiment.ts`; use `fanOf` to read, write buzz only.
- Stories (awards, records, history, HoF, highlights, social, inbox, fans/morale) live in `src/engine/stories/`; the season engine only calls `stories/hooks.ts`, and story randomness uses `storyRng` so it never shifts game results.
- Rotations: `Rotation.minutes` is the GM minutes plan (sums to 240), `Rotation.auto` lets the coach re-pick before every game; in-game energy/fatigue tunables are `FATIGUE` in `sim/game.ts`.
- GM logic lives in `src/engine/gm/` (cap, trade, roster/FA/waivers, draft, offseason); UI GM moves go through `useStore().act`.
- Random pop-up events live in `src/engine/events/` (catalog of plain data in `catalog/*.ts`, `engine.ts` rolls/resolves, `effects.ts`, `mods.ts` for temporary sim modifiers). Events only roll when the sim is run with `pauseForEvents` (the worker does; tests/scripts don't); outcomes are seeded so reloads can't re-roll; temporary buffs are `GameMods` into `simGame`, never rating edits. Spec: `docs/superpowers/specs/2026-11-23-random-events-design.md`.
- People (players, coaches, fans) have a `Heritage` (american/african/asian/latino/european) rolled first (`face/heritage.ts`, 50/12.5×4) and stored in the low 3 bits of `faceSeed`; names come from `NAME_POOLS`/`pickName` (`data/names.ts`, ~12% mixed), faces from the weighted tables in `face/tables.ts`. Heritage is only inferred from a name in the save migration (`face/backfill.ts`). `/dev/faces` has a heritage filter for eyeballing new art.
- Rivalries live in `src/engine/rivals/` (`data.ts` starting rivals, `rivalry.ts` heat/lookup/dynamic draw, `tilt.ts` vet vs new-guy tilt, `showing.ts` POT bump); state is `League.rivalry`. They reach the sim only via `GameMods.volatility` (never rating edits), and `buildMods` applies it to any rival game, AI included. Spec: `docs/superpowers/specs/2026-11-27-rivalries-design.md`.
- MyCareer (slice A) follows one player from draft night to retirement; state is the optional `League.career` (null in normal GM leagues), code in `src/engine/career/` (`build.ts` max-build + 25-floor start ratings, `careerOvr.ts` the single OVR seam — everything but the sim reads his Career OVR via `ovrOf`, never `computeOvr` (scan test enforces it), `draftNight.ts`, `play.ts` replay-pause day driver, `growth.ts` offseason aging, `training.ts` skill points (SP: 1+ per game he plays, more for beating his own average game score and cashing in moments; career `grow` effects pay SP instead of ratings) spent on trainings in the Development screen (3/7/12 SP = 1/3/6 random points into a group's skills with room left; the only way he grows), `contracts.ts` offers/sudden trade-or-cut, `offseason.ts`, `retirement.ts`, `endings.ts`). In-game moments are `GameMods.career` + `sim/moments.ts`, asked during the live broadcast (Play = watch: `startWatch` in a career league runs `careerPlayDay(..., { watch: true })`; while paused the log is a best-option preview that is exact up to `watch.moments[prompt.index]`, where `WatchGame` stops and asks) (hash-triggered, never the main `Rng`; `simGame` throws `MomentPause`, the driver re-sims the same seed with answers locked in). In a career league `gmTeamId(l)` is `''` so every GM-engine CPU routine manages all teams, while `userTeamId` follows the player; GM-altering UI moves go through `act` which refuses them unless marked `{ career: true }`. Spec: `docs/superpowers/specs/2026-11-27-mycareer-design.md`.
- Play styles (Smart/Offense/All-Around/Power/Defensive) live in `src/engine/player/playStyle.ts`: `Player.playStyle` is rolled once at generation from the position odds chart × a ratings fit vs position norms (seeded from `rawSeed`, never the league `Rng`; old saves roll from `hashId(id)` in the v16 migration; MyCareer picks his in the builder) and never changes. Habits (`applyHabits`) and boosts (`boostedRatings`, via `effectiveRatings` built once per game) exist only inside `simGame`; stored ratings, OVR, archetype detection, trade value and contracts never see them. UI: `StyleBadge`/`WithStyle` emoji in the portrait corner opposite the OVR, boosted stat names marked on the player page. Spec: `docs/superpowers/specs/2026-11-28-play-styles-design.md`.
- Save format is `League` (version 16) in IndexedDB; keep it JSON-serializable and bump `version` + add a migration if the shape changes.
